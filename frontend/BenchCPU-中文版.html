BenchCPU 方法论。

第一部分：配置空间与统计方法

▲

1.1 从静态配置到开放配置空间

BenchCPU 旨在推动公平、客观、统计严谨的 CPU 基准测试。传统 CPU 基准测试遵循静态工作负载配置范式：将代表性工作负载与固定数据集、特定并发级别绑定，报告单一聚合分数。在异构多核架构和快速演进的应用场景下，CPU 性能对评估配置极度敏感：固定配置掩盖了平均约 20% 的性能差距，并频繁产生统计偏倚结果，严重偏离 CPU 的真实性能分布。

BenchCPU 通过将基准测试解耦为多个正交、可扩展的维度，构造开放配置空间，以统计规整的采样方法刻画 CPU 性能的完整分布，来解决这些局限。核心思想：不再用单一配置代理 CPU 性能，而是将基准测试转化为开放配置空间上的分布统计。

BenchCPU 的配置空间是开放且显式的：所有维度中的所有可选参数均来自预定义集合。测试者可自由使用集合内的任意参数组合——不存在被禁止的编译器标志、数据集大小或并发级别。

1.2 配置空间定义：W × D × T × C

BenchCPU 的配置空间由四个正交维度构成，理论总配置空间约 123 万个配置。采用固定种子的分层随机采样从中抽取代表性配置样本。每轮从各维度独立采样。

维度符号含义采样方法范围
工作负载W基准测试程序本体每轮执行全部 54 个工作负载；不采样全部
数据规模D输入数据规模参数[base, base×2) 内 10 等分离散点；每轮随机选 1 个全部 54
线程T并行执行线程数每负载每轮独立随机整数 [1, 64]全部 54

一轮 = 全部 54 个工作负载各以当轮独立采样的（d, t, c₁, c₂）参数执行一次。四个维度参数按工作负载独立随机采样，且各轮完全独立。由于使用固定随机种子，所有轮的采样结果都是确定且可复现的。

开放性：配置空间中所有参数来自预定义、显式枚举的集合。此设计确保全面评测：CPU 必须在各种可能的配置下都表现良好，而不仅仅在少数「安全」配置下。

工作负载维度（W）

BenchCPU 包含 54 个工作负载，详见附录 A。工作负载分为基础工作负载（49 个，跨大版本固定）和新兴工作负载（5 个，每年更新）。测试者须声明评测了哪些层级。不允许选择工作负载子集——除非某个工作负载因可证明的平台兼容性问题无法运行。

数据维度（D）

每个工作负载有一个基础数据规模。每轮在 [base, base×2) 区间内生成 10 个等分离散点，随机选择其中一个。此设计使数据规模从约 1× 到近 2× 的基础值变化，有效覆盖从缓存友好的小数据集到内存密集型大数据集的连续谱。

线程 / 并发维度（T）

每个工作负载每轮独立从 [1, 64] 中随机抽取一个整数作为线程数。54 个工作负载彼此独立采样，各轮也相互独立。此设计确保完整覆盖全并发谱。

编译器维度（C）

仅适用于 C/C++ 工作负载。Python、Java 和 Go 工作负载不受此维度影响。两个子维度每轮独立采样：编译器选择（随机选择 clang 或 gcc）和优化级别（随机选择 -O1、-O2、-O3）。所有 C/C++ 工作负载同轮内共享相同的编译器选择和优化级别。

1.3 统计推断与分布感知

BenchCPU 的结果不是一个单一分数，而是 CPU 在开放配置空间上性能分布的统计刻画。方法论基于中心极限定理（CLT）：对于从配置空间抽取的足够样本量 n，样本均值近似服从正态分布：μ̂ ~ N(μ, σ²/n)。

一次合规的 BenchCPU 运行产生以下统计量：

  • 均值（μ）——所有采样配置的算术平均性能。
  • 标准差（σ）——刻画跨配置性能变异。
  • 95% 置信区间——[μ − t0.025,n-1·σ/√n, μ + t0.025,n-1·σ/√n]。这个区间有 95% 的置信度包含了真实均值。
  • 变异系数（CV = σ/μ）——相对离散度指标。
  • 最小值/最大值——观测性能极值。

1.4 基础空间与新兴空间

基础空间：由稳定锚定的工作负载及其配置维度组成，在 BenchCPU 大版本间保持固定，确保跨代 CPU 性能比较的长期连续性。

新兴空间：由动态演进的工作负载及其配置维度组成，每年更新以追踪前沿应用需求（如 AI 推理、图分析、无服务器计算）。

结果须明确标识评测了哪些空间。仅基础空间为发表最低要求；基础+新兴空间推荐用于全面评测。

1.5 动量过滤与跨版本稳定性

为维护跨版本稳定性，BenchCPU 应用动量过滤机制。当新兴空间更新时，前一周期 90% 的配置样本以权重保留，10% 的新配置逐步融合，从而抑制因工作负载更新导致的分布漂移，确保跨版本纵向可比性。

BenchCPU 使用固定随机种子从配置空间中确定性抽取配置样本集。给定相同的配置空间定义、相同随机种子和相同系统配置，结果可精确复现。结果采用累积提交模式。当相对误差 ≤ 10% 时，结果获得「统计充分」徽章。

2.1 评价学基础：EO / AO / COs / SCS / EC

BenchCPU 排行榜采用复杂系统评价学框架，使用五个核心概念：

概念对应实体说明
EO（评价对象）CPU 硬件被评价对象本身。在 BenchCPU 中，EO 即 CPU（型号、架构、核心/线程、频率、缓存层级）。
AO（受影响对象）最小独立运行计算机系统AO 是最小独立运行计算机系统，包括操作系统、操作系统设置、内存、内存设置、磁盘、磁盘设置等。
COs（干扰对象）基准应用（如工作负载、数据集、副本/线程）、编译器、编译器标志COs 指干扰对象：基准应用（工作负载、数据集、副本/线程）以及编译器与编译器标志。
SCS（自包含系统）SCS = EO + AO + COs可运行的自包含系统，包含 EO、AO、COs，用于复现实验观测效应。
EC（评价条件）EC = 去除 CPU 后的 SCSEC 是从 SCS 中移除 CPU（EO）后得到的评价条件。进行 EO 对比时，应尽量保证 EC 共享或等价。

2.2 CPU排行榜评测执行流程

  1. 配置样本生成：BenchCPU委员会使用固定随机种子，从配置空间中预生成一组配置样本集，然后在每个发布周期公开发布一轮配置样本。
  2. 用户评测：用户下载 BenchCPU基准测试程序和配置样本文件，并在本地 CPU 平台上运行。BenchCPU将自动完成全部工作负载在给定配置下的构建与执行，并自动采集负载运行时间、系统配置等信息。
  3. 结果提交：评测完成后，用户将BenchCPU自动采集的结果文件提交至BenchCPU委员会。
  4. 累积统计：服务端累积同一 CPU 平台的多次提交。设第 i 轮全部负载的平均执行时间为 X_i，按 n 轮累计计算：均值 μ = (1/n)·ΣX_i 、95% 置信区间 CI₉₅ = [μ−t0.025,n-1·σ/√n, μ+t0.025,n-1·σ/√n]。根据均值进行排名，并报告置信区间。
  5. 排名更新：每次新提交到达时，排名和统计量自动更新。

相对误差与累积轮数：相对误差 = 95% 置信区间半宽 / 样本均值。相对误差 ≤ 10% 表示 95% 置信区间半宽落在样本均值的 ±10% 以内。n=4 时：Xeon 8.61%，Kunpeng 5.21%，EPYC 9.47%。

排名资格：参与排名需同时满足两个条件：① 累积轮数 n ≥ 4；② 相对误差（RE）≤10%。满足后获得「统计充分」标记并进入正式排名。

2.3 CPU两两比较与显著性判断

采用对数比值法分析 CPU A（Intel Xeon Gold 5120T）与 CPU B（Kunpeng 920）的运行时间。先取 ln(TA,i / TB,i)，再在对数域求均值和 95% CI，最后指数还原。详见下表。

2.3.1 统计方法说明

步骤解释说明
1. 求比值对每个配对样本先计算 ri = TA,i / TB,i（每个 workload 共 16 轮；全量汇总为 54×16）。
2. 对比值取 ln令 xi = ln(ri) = ln(TA,i / TB,i)。这样做的原因是：t 区间基于算术平均，先在 ln 域求算术平均再指数还原，等价于在原始比值域求几何平均；且若改为 B/A，只需整体取倒数，结论保持对称。
3. 在对数域计算均值和 95% CId = (1/n) Σi=1n xi，sx = √((Σi=1n (xi - d)2) / (n - 1))，并计算 [lci, rci] = d ± t0.025,n-1 × sx / √n。
4. 指数还原到原始比值域Time A / Time B 的几何均值为 ed，其 95% CI 为 [el_ci, er_ci]。
5. 显著性判断1 落在 CI 内 -> 无显著差异；CI 全 > 1 -> A(Intel) 显著慢于 B(Kunpeng)；CI 全 < 1 -> A(Intel) 显著快于 B(Kunpeng)。

2.3.2 各Workload对数比值区间估计结果

Time A / Time B 整体几何均值为 0.70，95% CI = [0.66, 0.75]，A 比 B 快约 30%。在 54 个 workload 中，Intel 显著更快 36 个（67%），Kunpeng 显著更快 12 个（22%），无显著差异 6 个（11%）。
